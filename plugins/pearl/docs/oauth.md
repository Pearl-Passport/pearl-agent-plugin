# OAuth configuration

Pearl's MCP server is an OAuth 2.1 protected resource. It uses Authorization Code with PKCE `S256`, resource binding, and public-client token authentication (`none`). Dynamic Client Registration (DCR) is disabled.

No OAuth client secret belongs in this package. Public client IDs may be documented because they are identifiers, not credentials. Access tokens, refresh tokens, authorization codes, passwords, and private keys belong only in host-managed secure storage.

Pearl Agent access currently requires an eligible Pearl Access member. The server independently enforces admission, live Access eligibility, and granted scopes; a package or cached token cannot bypass those checks.

## Current host configuration

| Host | OAuth path | Static public registration |
| --- | --- | --- |
| Codex Desktop and CLI | Host CIMD plus `codex mcp login pearl` | None when CIMD succeeds |
| Claude web and desktop Chat | Pre-registered public client `pearl-claude-hosted` | Required; secret empty |
| Claude Code | Anthropic-hosted CIMD and ephemeral loopback callback | None |
| Cursor IDE, Agents, and Grok Bot | Pre-registered public client `pearl-cursor` | Required; no secret |

The current read scopes are:

- `venues:read`
- `profile:read`
- `visits:read`
- `saves:read`
- `friends:read`
- `trips:read`
- `reservations:read`

Do not request a write scope from this release.

## Codex

The preferred path uses the host's Client ID Metadata Document (CIMD). Run:

```bash
codex mcp login pearl
```

If a future Codex host cannot use CIMD, an operator must register the exact callback URI generated by that host and provide a public client ID. Never invent a callback, reuse another host's client, or place a secret in `.mcp.json`.

## Claude web and desktop Chat

| Field | Required value |
| --- | --- |
| OAuth Client ID | `pearl-claude-hosted` |
| OAuth Client Secret | **Leave empty** |
| Redirect URI | `https://claude.ai/api/mcp/auth_callback` |
| Token authentication | `none` |
| PKCE | `S256` |

Enter the exact public client in Advanced settings. Do not attempt an empty-client registration flow; the DCR endpoint remains disabled.

## Claude Code CIMD

Claude Code uses Anthropic-hosted CIMD and an RFC 8252 loopback callback on an ephemeral port. Trusted metadata declares both `http://localhost/callback` and `http://127.0.0.1/callback`; only the runtime port varies.

```bash
claude mcp login plugin:pearl:pearl
```

The installed plugin server is namespaced as `plugin:pearl:pearl`. Do not add `--client-id`, `--client-secret`, or `--callback-port` for the normal Claude Code flow.

If automatic CIMD discovery fails, Claude Code also supports a separately pre-registered public client. That fallback requires an operator to choose and register an exact callback such as `http://localhost:8080/callback`, then pass the matching public client ID and fixed port:

```bash
claude mcp add --transport http \
  --client-id REGISTERED_PUBLIC_CLIENT_ID \
  --callback-port 8080 \
  pearl https://agent.joinpearl.co/mcp
```

Do not reuse `pearl-claude-hosted`, do not pass `--client-secret`, and do not invent a client registration. Pearl has not published this fallback client; the normal CIMD path remains primary.

## Cursor and Grok Bot

| Field | Required value |
| --- | --- |
| OAuth Client ID | `pearl-cursor` |
| OAuth Client Secret | **None; do not create or track one** |
| Web / Agents redirect URI | `https://www.cursor.com/agents/mcp/oauth/callback` |
| Desktop app redirect URI | `http://localhost:8787/callback` |
| Token authentication | `none` |
| PKCE | `S256` |
| Scopes | `venues:read profile:read visits:read saves:read friends:read trips:read reservations:read` |

Register both callbacks exactly. Grok Bot uses the hosted Cursor callback and does not receive a separate OAuth client.

The Cursor manifest intentionally names both the plugin and its MCP server `pearl-cursor`. This separates Cursor's static public-client configuration from the URL-only `pearl` server used by Codex and Claude Code. All wrappers still resolve to the single production endpoint above.

## Security boundaries

- The package does not register clients, issue tokens, store grants, or implement OAuth.
- The package does not enable a tool or broaden a live grant.
- Never add a client secret, token, authorization header, environment file, or callback override to the repository.
- Runtime `tools/list`, OAuth scopes, and server-side eligibility remain authoritative.
